# SQLmakerJ

Gerador de scripts SQL `CREATE TABLE` para **MySQL**, **PostgreSQL** e **Oracle**, feito em **Java com Spring Boot** e **React**.
Você monta as tabelas e as colunas na tela e o próprio Java escreve o script na sintaxe do banco escolhido, sem nenhuma IA.

O SQLmakerJ é a versão só em Java do SQLmaker, um projeto meu que também gera SQL com IA (IBM watsonx).
Aqui ficou apenas o modo manual: toda a regra de geração e de validação está no backend, escrita à mão.

## Funcionalidades

- **Três bancos:** MySQL 8.0, PostgreSQL 16 e Oracle 19c, cada um com o próprio dialeto.
- **Editor de tabelas:** adicione tabelas e colunas, escolha o tipo e marque as opções de cada coluna:
  - **PK:** chave primária, simples ou composta;
  - **FK:** chave estrangeira para uma coluna PK ou única de outra tabela;
  - **Obrigatório:** `NOT NULL`;
  - **Único:** `UNIQUE`;
  - **Automático:** `AUTO_INCREMENT` no MySQL, `GENERATED BY DEFAULT AS IDENTITY` no PostgreSQL e no Oracle.
- **Ordem pelas chaves estrangeiras:** cada tabela é criada depois das tabelas que ela referencia.
  Quando há referência circular, a chave estrangeira vai para o fim do script, com `ALTER TABLE`.
- **Explicação do script:** cada resposta diz em português o que foi gerado e como o banco trata os tipos usados.
- **Validação completa:** todos os problemas da estrutura voltam de uma vez, com a tabela e a coluna de cada um.
- **Download:** o script sai em `.sql` e pode ser baixado também em `.zip`.
- **Tema claro e escuro**, que segue o sistema ou fica salvo pelo botão do topo.
- **Página de contato** com e-mail, GitHub e LinkedIn. O formulário de mensagem ainda não envia e mostra um aviso.

## Tipos de coluna

A tela usa tipos genéricos, e cada banco traduz o tipo para a própria sintaxe:

| Tipo na tela | MySQL 8.0 | PostgreSQL 16 | Oracle 19c |
| --- | --- | --- | --- |
| `INT` | `INT` | `INTEGER` | `NUMBER(10,0)` |
| `BIGINT` | `BIGINT` | `BIGINT` | `NUMBER(19,0)` |
| `VARCHAR(n)` | `VARCHAR(n)` | `VARCHAR(n)` | `VARCHAR2(n CHAR)` |
| `CHAR(n)` | `CHAR(n)` | `CHAR(n)` | `CHAR(n CHAR)` |
| `TEXT` | `TEXT` | `TEXT` | `CLOB` |
| `DECIMAL(p,s)` | `DECIMAL(p,s)` | `NUMERIC(p,s)` | `NUMBER(p,s)` |
| `BOOLEAN` | `BOOLEAN` | `BOOLEAN` | `NUMBER(1,0)` com `CHECK (coluna IN (0, 1))` |
| `DATE` | `DATE` | `DATE` | `DATE` |
| `DATETIME` | `DATETIME` | `TIMESTAMP` | `TIMESTAMP` |

Limites de tamanho conferidos por banco:

| | MySQL | PostgreSQL | Oracle |
| --- | --- | --- | --- |
| `VARCHAR` | 16.383 | 10.485.760 | 4.000 |
| `CHAR` | 255 | 10.485.760 | 2.000 |
| `DECIMAL` (precisão) | 65 | 1.000 | 38 |

## Regras de validação

Antes de gerar, o backend confere a estrutura inteira e devolve todos os problemas juntos. Entre as regras:

- nomes de tabelas e colunas com letras sem acento, números e `_`, começando por letra, com até 63 caracteres (o limite do PostgreSQL, o menor dos três);
- nenhuma palavra reservada do banco escolhido como nome (por exemplo, `USER` no Oracle);
- sem tabelas repetidas e sem colunas repetidas na mesma tabela;
- toda tabela com pelo menos uma coluna PK;
- tamanho obrigatório em `VARCHAR`, `CHAR` e `DECIMAL`, dentro do limite do banco, e proibido nos outros tipos;
- só uma coluna automática por tabela, do tipo `INT` ou `BIGINT`, e ela precisa ser a única PK ou estar marcada como única;
- `TEXT` não pode ser PK nem único no MySQL e no Oracle;
- a chave estrangeira precisa apontar para uma coluna que existe, do mesmo tipo, e que seja a única PK da tabela ou esteja marcada como única;
- até 50 tabelas por arquivo e 100 colunas por tabela.

## Como rodar

### Pré-requisitos

- **JDK 25** (o Maven vem junto pelo wrapper `mvnw`);
- **Node.js 20.19+ ou 22.12+** e npm.

### 1. Backend

```bash
cd backend
./mvnw spring-boot:run        # no Windows: .\mvnw.cmd spring-boot:run
```

A API sobe em `http://localhost:8081`. A porta pode ser trocada pela variável de ambiente `PORT`.
Não há chave, banco de dados ou serviço externo para configurar.

### 2. Frontend

Em outro terminal:

```bash
cd frontend
npm ci
npm run dev
```

Abra o endereço que o Vite mostrar (normalmente `http://localhost:5173`).
Em desenvolvimento, o Vite encaminha tudo o que começa com `/api` para o backend na porta 8081.

### Outros comandos

| Onde | Comando | O que faz |
| --- | --- | --- |
| `backend/` | `./mvnw test` | Roda os testes |
| `backend/` | `./mvnw package` | Gera o JAR em `target/` |
| `frontend/` | `npm run lint` | Confere o código com o Oxlint |
| `frontend/` | `npm run build` | Confere os tipos e gera o site em `dist/` |

## API

| Método | Rota | O que faz |
| --- | --- | --- |
| `GET` | `/api/status` | Confere se a API está no ar |
| `POST` | `/api/manual/gerar` | Gera o script a partir das tabelas |
| `POST` | `/api/arquivos/sql` | Devolve um script como arquivo `.sql` |
| `POST` | `/api/arquivos/zip` | Devolve um ou mais scripts dentro de um `.zip` |

### Gerar um script

`POST /api/manual/gerar`

```json
{
  "banco": "MYSQL",
  "nomeArquivo": "escola",
  "tabelas": [
    {
      "nome": "curso",
      "colunas": [
        { "nome": "id", "tipo": "INT", "chavePrimaria": true, "autoIncremento": true },
        { "nome": "nome", "tipo": "VARCHAR", "tamanho": 100, "obrigatorio": true }
      ]
    },
    {
      "nome": "aluno",
      "colunas": [
        { "nome": "id", "tipo": "INT", "chavePrimaria": true, "autoIncremento": true },
        { "nome": "email", "tipo": "VARCHAR", "tamanho": 150, "unico": true },
        { "nome": "ativo", "tipo": "BOOLEAN", "obrigatorio": true },
        { "nome": "curso_id", "tipo": "INT", "obrigatorio": true,
          "referencia": { "tabela": "curso", "coluna": "id" } }
      ]
    }
  ]
}
```

- `banco`: `MYSQL`, `POSTGRESQL` ou `ORACLE`.
- `tipo`: `INT`, `BIGINT`, `VARCHAR`, `CHAR`, `TEXT`, `DECIMAL`, `BOOLEAN`, `DATE` ou `DATETIME`.
- `tamanho`: usado em `VARCHAR`, `CHAR` e `DECIMAL`; no `DECIMAL` é a precisão, e `escala` são as casas decimais.
- As opções `chavePrimaria`, `autoIncremento`, `obrigatorio` e `unico` valem `false` quando não são enviadas.

Resposta:

```json
{
  "banco": "MYSQL",
  "versao": "8.0",
  "arquivos": [
    {
      "nome": "escola.sql",
      "conteudo": "-- Gerado pelo SQLmakerJ para MySQL 8.0\n\nCREATE TABLE curso (\n ..."
    }
  ],
  "explicacao": "O script cria 2 tabelas no MySQL 8.0, nesta ordem: curso e aluno. No MySQL, BOOLEAN é um apelido de TINYINT(1): TRUE e FALSE são gravados como 1 e 0."
}
```

O script gerado:

```sql
-- Gerado pelo SQLmakerJ para MySQL 8.0

CREATE TABLE curso (
    id   INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);

CREATE TABLE aluno (
    id       INT AUTO_INCREMENT PRIMARY KEY,
    email    VARCHAR(150) UNIQUE,
    ativo    BOOLEAN NOT NULL,
    curso_id INT NOT NULL,
    FOREIGN KEY (curso_id) REFERENCES curso (id)
);
```

### Erros

Os erros seguem o formato `ProblemDetail` (RFC 9457). Quando a estrutura tem problemas, a lista completa vem em `erros`:

```json
{
  "status": 400,
  "title": "Estrutura das tabelas inválida",
  "detail": "A estrutura tem 3 problemas.",
  "instance": "/api/manual/gerar",
  "erros": [
    "Tabela \"user\": USER é uma palavra reservada no Oracle. Escolha outro nome.",
    "Tabela \"user\", coluna \"nome\": no Oracle, CLOB não pode ser PK nem Única. Escolha um texto com tamanho.",
    "Tabela \"user\": marque pelo menos uma coluna como PK."
  ]
}
```

Campos inválidos no próprio JSON (por exemplo, um nome em branco) voltam com status 400 e a lista de campos em `campos`.

### Baixar os arquivos

`POST /api/arquivos/sql` recebe `{ "nome": "escola.sql", "conteudo": "..." }` e devolve o arquivo para download.

`POST /api/arquivos/zip` recebe `{ "arquivos": [{ "nome": "escola.sql", "conteudo": "..." }] }` e devolve `SQLmakerJ.zip`.

## Testes

```bash
cd backend
./mvnw test
```

Os testes de `GeracaoManualServiceTest` cobrem:

- o script nos três bancos;
- a ordem das tabelas pelas chaves estrangeiras;
- a chave primária composta;
- a referência circular com `ALTER TABLE`;
- os limites de cada banco;
- o tipo igual na chave estrangeira;
- as regras da coluna automática;
- a validação que junta todos os problemas.

O `BackendApplicationTests` confere se a aplicação sobe.

## Publicar na Vercel

O `vercel.json` publica o frontend e o backend no mesmo projeto. O frontend é compilado pelo Vite e servido como site estático, e as rotas `/api` vão para o backend, que roda em container pelo `backend/Dockerfile.vercel`.

1. Importe o repositório em [vercel.com/new](https://vercel.com/new), com a raiz do repositório como Root Directory.
2. Em Environment Variables, cadastre `PORT` com o valor `8080`.
3. Clique em Deploy.

Containers e Services ainda estão em beta na Vercel.
